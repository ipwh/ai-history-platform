# 教師回饋與品質閘門校準計劃（Sprint 8.6）

本文件說明**將來**如何把歷史科教師的真實決定，與自動品質閘門的判定逐項比較，從而找出閘門
在真實教材與真實題目上的偏差。它不是「準確率報告」：平台目前**沒有**任何教師覆核紀錄，
因此本文不提供任何比率、命中率或信心分數，亦不會據此自動調整發布門檻。

---

## 1. 為甚麼要分開記錄

自動閘門只做確定性的字面檢查（教材依據、答案一致性、抄錄幅度、解釋是否說明推理、教材是否
支持題目要求的思考面向等）。它**不是**史實判斷，也不是教學判斷。因此「機器說可用」與
「教師認為可用」是兩件獨立的事，必須分開記錄，才看得出閘門在哪裡出錯：

| 情況 | 意義 | 目前的處理 |
| --- | --- | --- |
| 機器 `pass` → 教師 `reject` | **假通過**：閘門漏掉的缺陷 | 立即下架該題並記錄例子；這是最高價值的校準資料 |
| 機器 `revise`／`reject` → 教師 `approved` | **假攔截**：閘門過度保守 | 記錄例子；只可用來檢視規則，不可為此放寬安全規則 |
| 機器判定與教師一致（可用／不可用） | 一致 | 記錄分母，用於日後比較（**不**現在計算比率） |
| 教師發現史實錯誤 | 內容錯誤（與閘門無關，閘門無法判斷史實） | 修正題目、下架、記錄 |
| 教師發現答案不完整／含糊 | 題目設計問題 | 改寫或停用，記錄 |
| 教師發現錯誤選項薄弱 | 選項設計問題 | 改寫，記錄 |
| 教師發現解釋無助理解 | 解釋質素問題 | 改寫，記錄 |
| 教師發現難度或課程不符 | 課程對應問題 | 調整難度或停用，記錄 |

## 2. 記錄格式（逐題，不預填）

每一條被教師看過的題目，記錄一筆（格式建議見
`docs/teacher-review/generated-question-sample-2026-10.json` 的 `reviewChecklist`）：

| 欄位 | 內容 | 由誰填 |
| --- | --- | --- |
| `questionId`／`revision` | 題目及被審的版本 | 系統（唯讀產生） |
| `gateAtGeneration` | 生成時的閘門結果（暫緩標記、品質警告） | 系統 |
| `gateRecomputedNow` | 以現行規則重算的結果（`pass`／`revise`／`reject` 及代碼） | 系統 |
| `reviewChecklist` | 七項審題準則 | **教師** |
| `reviewerDecision` | `approved`／`needs-revision`／`reject` | **教師** |
| `reviewComments`／`outstandingConcerns` | 具體意見及待辦 | **教師** |
| `reviewer`／`reviewedAt` | 覆核者及日期（不得留空、不得代填） | **教師** |

平台內的覆核紀錄（`question_reviews`）同樣會記錄版本、內容指紋、決定、原因、覆核者及時間，
兩者可以互相對照。

## 3. 校準類別（評估用的標籤，不是結果）

以下標籤用來描述每一筆差異，**不可以**在取得教師決定之前預先填上：

1. `false-pass`：機器 `pass`，教師認為不可用（細分：史實錯誤、答案不完整、選項薄弱、解釋無用、難度／課程不符）。
2. `false-hold`：機器 `revise`／`reject`，教師認為可用（細分：改寫答案、跨段證據、教材以標題帶出因果、教材用字差異）。
3. `agreement-usable`：雙方都認為可用。
4. `agreement-unusable`：雙方都認為不可用。
5. `human-only-defect`：只有人能發現的問題（史實、課程、教學法），閘門原則上不負責。

## 4. 已記錄的固有限制（不需要教師決定，但必須如實說明）

- **改寫答案**：選擇題答案若是教材語句的改寫（文字重疊率 ≥ 60%），一律暫緩交教師確認——即使改寫完全正確。
- **跨段證據**：平台的契約要求節錄逐字出自**單一**段落；需要兩段才能完整作答的題目，只能把背景寫在題幹內。
- **標題帶出的因果**：教材以標題（例如「……的條件」）列出原因時，標題不計入教材單位，因此「為甚麼」類題目仍可能被暫緩。
- **教材欄目標題作答案**：填充題答案若是教材欄目標題（例如「社會及文化方面」），品質閘門不會攔截（該規則只在本地示範生成中使用）。
- **歸屬語氣**：教材寫「學者認為……」屬歸屬而非推測，是否保留由教師判斷。
- **同義與等值**：同義詞、不同譯名、等值措辭的判斷屬語意工作，字面規則只會暫緩，不會自行接受。

## 5. 使用校準結果的規則（防止小樣本過度推論）

1. **不得**在少於 30 條**已覆核**題目時公布任何比率或「準確率」。
2. **不得**因為一兩條 `false-hold` 就放寬安全規則（尤其是教材依據、答案一致性、版權閘門）。
3. **不得**自動調整發布門檻、自動改寫題目或自動停用題目；任何規則修改都要有明確的缺陷證據、
   對應的迴歸測試，並記錄在 README 的缺陷日誌。
4. 任何新規則都必須同時加入「反例樣本」（見 `question-quality-fixtures.v1.json`），證明它不會
   把正確的題目或教材用語誤判。
5. 校準結果只是**改進規則的輸入**，不是發布授權：發布仍然需要教師覆核或已記錄的自動驗證。

## 6. 現時狀態

- 已準備：8 條真實生成題目的完整覆核套件（`generated-question-sample-2026-10.json`），
  內含生成時與現行規則的機器判定，方便教師對照。
- 已準備：31 個對照樣本的逐項校準紀錄（`fixture-calibration-2026-10.json`）。
- **未開始**：教師覆核（平台沒有可用的歷史科教師覆核者），因此：
  - `false-pass`／`false-hold` 的實際分佈**未知**；
  - 不可聲稱閘門「準確」或題目「已獲教學驗證」；
  - 首次教師覆核完成後，應以本文件的類別記錄第一批結果，並只作個案檢視（不計算比率）。
