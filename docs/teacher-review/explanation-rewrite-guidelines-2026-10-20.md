# 解釋補寫指引及技能標籤確認（2026-10-20）

> 給歷史科教師及日後協助起草的 AI 工具使用。**所有內容必須由教師確認後才可寫入題庫。**
> 相關工具：`npm run audit:explanation-worklist`（產生清單）、
> `npm run flag:content-improvement`（標記進度）。
> 背景數據見 [docs/quality/explanation-skill-diagnosis-2026-10-20.md](../quality/explanation-skill-diagnosis-2026-10-20.md)。

## 一、不可跨越的界線

| 可以 | 不可以 |
| --- | --- |
| 改寫 `explanation` | 改動 `correctAnswer` |
| 補充歷史背景、因果、概念定義 | 改動 `options`（選項文字或次序） |
| 引用課本原文（並註明章節） | 改動題幹中的空格位置或數量 |
| 建議並確認 `skill` 標籤 | 由程式或 AI 自行寫入 `skill` |
| 標記「待重寫」／「已補寫」 | 用標記代替教師覆核（`question_reviews`） |

任何影響評分的修改（答案、選項、空格）都必須另外走教師覆核流程，並在紀錄中說明理由。

## 二、補寫原則

1. **先說「為甚麼」，不要只換句話重複答案。**
   ❌「答案是史前時期，因為這是史前時期。」
   ✅「史前時期沒有人類文字紀錄，因此無法以文獻研究；歷史學家便以考古發現（石器、遺骸）重建這段時期。」

2. **連結課本的概念、因果、時間背景或史料特徵。**
   每題至少連到一個課程概念（時序、因果、比較、轉變與延續、一手／二手資料）。

3. **長度以 40–90 字為宜**（中一至中三程度）。過長會令學生跳過。

4. **用繁體中文、語氣平實。** 避免「眾所周知」「很明顯」這類無助理解的措辭。

5. **不要引入課本沒有的史實。** 如不確定，寧可只寫概念關係，並在題目標記
   「需教師裁決」交給科組。

6. **不要寫成評分標準。** 「本題 2 分，答對關鍵詞得 1 分」屬評卷參考，不是解釋。

## 三、按「建議改進類型」的寫法

### A. 需補概念定義（1,217 題，主要為填充題）

結構：**這是甚麼 → 為甚麼它重要／與甚麼有關**

> 例（`qb-JTH2ndEdFBQ01007`，答案「一手資料」）
> 一手資料是指出自所研究時代的原始材料，例如當時的物件、官方紀錄及日記。
> 因為它未經後人轉述，最能反映當時的實況，所以是歷史研究最直接的證據。

### B. 需補因果／歷史推理（658 題，主要為「只列答案」的解釋）

結構：**背景／原因 → 結果 → 為甚麼這個結果可以理解**

> 例（`qb-JTH2ndEdFBQ09088`，答案「綏靖政策」）
> 1930 年代美國自身陷於經濟大衰退，無力亦無意介入歐洲事務，因此對極權國家的侵略
> 只作譴責而沒有實際行動。這種回應反映美國孤立主義的立場，亦令侵略者更肆無忌憚。

### C. 需補時間背景（暫無）

結構：**在此之前 → 這件事 → 在此之後／延續**

### D. 可依來源句改寫（暫無：現時沒有可用的課文原文）

如日後匯入附有課文段落的題目，結構為：**引原文 → 指出關鍵詞 → 說明它如何支持答案**。

## 四、AI 起草的 prompt 範本（**不自動發布**）

只可用於**單題或小批次（≤20 題）**的草稿，並必須由教師逐題確認。
**不可**對 1,300+ 題直接執行並寫入。

```text
你是香港中一至中三歷史科的教材編輯。請為以下題目補寫一段解釋，供課本自學使用。

硬性規則：
1. 不可以改變正確答案、選項或題幹中的空格；你只會輸出解釋文字。
2. 只可使用我提供的課本段落內容；如資料不足，請輸出「需教師補充：<原因>」
   而不是自行補充史實。
3. 繁體中文，40–90 字，語氣平實，適合中一至中三學生。
4. 必須包含「為甚麼這個答案成立」的說明（因果、目的或影響），不可只重複答案。
5. 不可以寫成評分標準或提及分數。
6. 不可以提及「校內試題」「評卷參考」等內部用語。

輸出格式（只輸出 JSON）：
{"explanation": "……", "concepts": ["因果關係", "…"], "confidence": "high|medium|low",
 "needsTeacherInput": true|false}

題目資料：
- 課題：{{topicTitle}}
- 分節／知識點：{{sectionTitle}} / {{knowledgePoint}}
- 題型：{{questionType}}
- 題幹：{{question}}
- 正確答案：{{correctAnswer}}
- 現有解釋：{{currentExplanation}}
- 課本段落（可能為空）：
{{textbookExcerpt}}
```

教師收到草稿後必須：

1. 對照課本核實每一句史實；
2. 確認沒有改動答案或選項；
3. 用教師端「編輯題目」功能儲存（版本 +1、回到草稿、須重新覆核或重新執行品質驗證）；
4. 用 `npm run flag:content-improvement -- --flag explanation_needs_rewrite --clear --ids <id> --reason "<理由>"` 解除標記。

> **為甚麼要回到草稿**：解釋屬題目內容指紋的一部分，改寫後舊覆核立即失效。
> 這是刻意設計——不能讓學生看到「覆核後已改變」的內容。

## 五、技能標籤確認

### 可選值（必須逐字相同，單選）

1. 正確地使用歷史辭彙
2. 準確排列歷史事件的次序
3. 描述歷史地圖、模型、圖形、圖表、圖畫、表格和漫畫的特徵
4. 從歷史資料中作出歸納和推論
5. 找出主要歷史事件和人物不同的解釋
6. 分辨歷史事實與見解之間的不同
7. 掌握資料的含義，對資料的準確性及可信性進行合理的質疑與探究
8. 運用想像力重組往事
9. 選取、組織和運用資料，並有條理地表達出來

### 判斷原則

- **只選一個、只選最有代表性的一個**。一題若同時涉及兩項，選「學生必須做到才能答對」的那一項。
- **寧可留空，不要硬填**。留空（`null`）只令技能統計少一題；填錯會令學生的弱項分析出錯。
- **不要為湊數而標第 3、5、7、8、9 項**：現有選擇題／填充題沒有附史料，實際上考核不到
  這些技能。如認為某題真的考核得到，請在理由中說明學生看到甚麼資料。
- 建議清單的信心說明：
  - **中**：填充題答案是一個歷史名詞 → 「正確地使用歷史辭彙」
  - **低**：選擇題未命中任何關鍵詞 → 仍是推測，必須逐題看題幹

### 寫入方式

技能只能經教師端編輯題目寫入（`updateManualQuestion`），不接受批次腳本直接改
`questions.skill`。這是刻意的：技能標籤會直接影響學生的學習分析，
必須有人看過題目才可決定。

## 六、建議工作流程

```bash
# 1. 產生／更新工作清單（唯讀）
npm run audit:explanation-worklist

# 2. 把第一批（例如課題1 的 50 題）標記為「解釋待重寫」（預設模擬）
npm run flag:content-improvement -- --flag explanation_needs_rewrite --limit 50 \
  --reason "2026-10 內容稽核：解釋為佔位文字（課題1 第一批）"

# 3. 確認輸出後真正寫入（必須提供 --actor）
npm run flag:content-improvement -- --flag explanation_needs_rewrite --limit 50 \
  --reason "2026-10 內容稽核：解釋為佔位文字（課題1 第一批）" \
  --actor teacher@pochiu.edu.hk --apply

# 4. 教師逐題補寫、儲存（版本遞增，須重新覆核）

# 5. 補寫完成後解除標記
npm run flag:content-improvement -- --flag explanation_needs_rewrite --clear \
  --ids qb-xxxx,qb-yyyy --reason "已按課本第 X 節補寫" \
  --actor teacher@pochiu.edu.hk --apply

# 6. 查看進度
npm run flag:content-improvement -- --list
```

教師端亦可經 `GET/POST /api/teacher/content-improvement` 以批次方式檢視及標記
（需教師或管理員登入；學生一律 403）。
