# 學伴教材檢索與證據架構（Sprint 34）

本文件描述學生提問由輸入到「引用哪幾段教材」的完整決策鏈，以及每個決策點的可觀測欄位。
它反映 **Sprint 34 修正後、再經 2026-11-10 詞彙未命中與程度優先修正**的實際程式碼（`src/server/services/tutor-grounding.ts`、
`tutor-query.ts`、`tutor-answerability.ts`、`tutor-query-expansion.ts`、
`tutor-web-supplement.ts`、`src/app/api/tutor/chat/route.ts`）。

> 為什麼要有這份文件：Sprint 33 的真實模型評估發現「教材明明有段落，回覆卻說找不到」。
> 追查時最耗時的不是修程式碼，而是**不知道決策鏈上哪一層做了甚麼判斷**。以下每一層
> 都對應一個可測試、可記錄的欄位。

## 1. 決策鏈總覽

```
學生提問（原文）
  │
  ├─① 正規化        normalizeTutorQuery          繁簡統一、全半形、英文縮寫、粵語→書面語
  ├─② 主題硬閘      isHistoryTopicPrompt / isClearlyNonHistoryTutorQuery / isUnclearTutorQuery
  │                    ├─ 已有教材片段 → 一律不判離題（2026-11-10）
  │                    ├─ out-of-scope（固定引導句，零模型呼叫、不扣額度）
  │                    └─ D 狀態（單一澄清問題，零模型呼叫）
  │                         └─ 但提問含教材詞彙 → 先做一次語意改寫（⑨）再決定是否澄清
  ├─③ 詞庫檢索詞    extractQueryTerms + HISTORY_TERM_GROUPS（含英文別名）
  ├─④ 課題推斷      guessTutorTopic（分節標題／教師關鍵詞／詞庫專名／「課題N」；
  │                 2026-11-10 起同程度優先、學生選定課題優先）
  │                    └─ 失敗 → ⑤
  ├─⑤ 教材內文反推  inferTopicFromMaterial（Sprint 34 新增；零模型呼叫）
  │                    └─ 條件：名詞類檢索詞、勝出課題 ≥2 段、且為第二名的兩倍（同程度優先）
  ├─⑥ 跨課題擴充    supportingTopicIds（比較題最多兩個課題）
  ├─⑦ 選段           selectTutorPassages（分數門檻 MIN_HIT_SCORE=6、長度折算、去重、上限）
  │                    └─ 0 段 → 回到 ⑤ 再試一次（僅限推斷來自課程用語時）
  ├─⑧ 證據充分度     assessMaterialSupport（A／B 判定：direct／inferential／insufficient）
  ├─⑨ 語意改寫      expandTutorQuery（⑦ 仍為 not-covered，或 ② 原本要走澄清但含教材詞彙；
  │                 2.5 秒預算、fail-open；命中後重算 ⑧）
  ├─⑩ 外網補充      collectTutorWebSupplement（白名單、not-covered-only、1.5 秒預算）
  └─⑪ 提示詞        buildTutorSystemPrompt（教材片段／外部參考／政策分區）
```

## 2. 各層輸入、輸出與失敗模式

| 層 | 輸入 | 輸出 | 失敗模式（如何處理） |
| --- | --- | --- | --- |
| ① 正規化 | 學生原文 | 繁簡統一、去標點的查詢字串 | 空字串 → 當作含糊處理 |
| ② 主題硬閘 | 正規化提問＋已有片段 | `history` / `out-of-scope` / `D` | 判為非歷史 → 固定引導句（零呼叫）；含糊 → 澄清（零呼叫）。**已有片段時永不判離題**（2026-11-10） |
| ③ 檢索詞 | 正規化提問 | `QueryTerm[]`（詞、權重 1–20） | 無詞 → 不推斷課題，走 C |
| ④ 課題推斷 | 提問＋課程索引＋學生程度＋（如有）學生選定課題 | `TutorTopicGuess` 或 `null` | `null` → 進入 ⑤；同程度課題達最高分一半即優先；推斷分數 < 16 時改以學生選定課題重試 |
| ⑤ 教材內文反推 | 名詞類詞＋全部可發布段落＋學生程度 | 課題或 `null` | 證據分散（未達兩倍）→ `null` → C（寧可保守）；同程度課題達勝出者一半段落即優先 |
| ⑥ 跨課題擴充 | 提問＋主課題 | 最多兩個課題 | 無額外證據 → 只用主課題 |
| ⑦ 選段 | 候選段落＋檢索詞 | 1–N 段（依深度上限） | 0 段 → 回到 ⑤ 重試；仍 0 段 → C |
| ⑧ 證據充分度 | 提問＋所選段落 | `evidenceSupport` | 關係不被支持／關鍵詞缺口 → B |
| ⑨ 語意改寫 | 提問＋課題標題 | 教材用語詞表 | 逾時／錯誤／空／格式錯 → 靜默降級（fail-open）；命中後重算 ⑧ |
| ⑩ 外網補充 | 提問＋grounding 狀態 | 白名單摘錄 | 任何失敗 → `failed`，主回答照常 |
| ⑪ 提示詞 | 以上全部 | system prompt | — |

## 3. 可觀測診斷（`selectionAudit`）

`findTutorGrounding` 回傳的 `TutorGrounding.selectionAudit` 只在伺服器內使用（不寫入
資料庫、不回傳給學生），測試與診斷可直接核對：

| 欄位 | 意義 |
| --- | --- |
| `candidateBlocks` / `scoredHits` / `belowThreshold` | 候選段落、通過門檻數、被門檻排除數 |
| `searchedTopicIds` | 實際檢索過的課題（跨課題比較時多於一個） |
| `topicAllocation` | 各課題的合格命中與實際選入段落數 |
| `selected[]` | 選入段落：分數、原始長度、送去模型的長度、是否截取、窗口起句 |
| `excluded[]` | 被排除的段落及原因（`max-sources`／`duplicate`／`already-used`／`too-short`） |
| **`topicInference.source`** | `curriculum`／`preferred-topic`／`context`／`material-fallback`／`none` |
| **`topicInference.fallbackCandidates`** | 教材內文反推時各課題的合格段落數（由多至少） |
| **`topicInference.fallbackTerms`** | 教材內文反推實際使用的檢索詞 |

診斷資料不含 secrets、學生個人資料或教材全文。

## 4. 三條不可交換的證據界線

1. **教材片段 ≠ 一般歷史知識**：C 狀態（教材未涵蓋）仍必須作答，但要標明是一般歷史
   知識；A／B 狀態引用片段時不可寫成「史上公認」。
2. **外部網站 ≠ 教材**：外網摘錄只出現在提示詞的「外部參考摘錄——非校本教材」區塊，
   `meta`／`done` 事件把它放在 `webSources`，教材出處放在 `sources`。摘錄內的任何
   句子都只是資料，不是指令（提示詞明文禁止遵從）。
3. **關鍵詞重疊 ≠ 事實支持**：`evidenceSupport` 會核對提問所問的關係（因果／比較／
   評價）是否真的出現在片段中；關鍵詞齊全但沒有交代關係 → B 並要求披露。

## 6. 2026-11-10 追加：詞彙未命中與程度優先

以 38 條學生實際問法（粵語／簡體／間接／錯字／追問＋3 條非歷史對照）模擬後，這一節記錄新增的
三個決策點。它們都在**零模型呼叫**的前提下運作，只有 ⑨ 語意改寫需要一次模型呼叫。

1. **`grounded` ⇒ 不判離題**：② 只在「沒有任何可用片段」時才決定 `out-of-scope`。理由：詞庫覆蓋
   永遠有限，若檢索已找到教材卻仍以「詞彙不像歷史」拒答，是最容易被學生視為故障的行為。
2. **教材詞彙命中 ⇒ 不以離題處理**：`messageUsesAnyCourseVocabulary` 在「無課題錨點 + not-covered +
   提問句式」時檢查提問是否用了教材出現過的歷史詞（`HISTORICAL_PROPER_TERMS`／
   `HISTORICAL_EVERYDAY_TERMS`，後者要求疑問句式，避免「我今日好開心」被當成歷史）。
   命中即走 C（一般歷史知識＋披露「教材未涵蓋」），並把命中的課題作為澄清候選。
3. **澄清前先試語意改寫（`reservedBeforeClarify`）**：D 狀態且含教材詞彙時，先用一次 ⑨ 重試檢索；
   命中就照 A／B／C 作答並重算 ⑧，未命中才回澄清問題。失敗的改寫不扣每日額度（每日 15 次只計
   已作答的提問），只計入 `ai_operations` 的反濫用時間窗；同一次請求不會重複預留額度。
4. **同程度優先**：`studentLevel`（由班別 `1A`–`6D` 推得，見 [student-level.ts](../src/lib/student-level.ts)）
   會傳入 ④ 與 ⑤。規則一致：**同程度課題的分數（或段落數）達最高者一半即優先**，否則維持原本
   排序。這令中一至中三學生問「凡爾賽條約」時取初中課題9，而不是向來「關鍵詞最精確」的高中課題。
5. **學生選定課題優先**：由練習頁／溫習課題進入時（`preferredTopicId`），若 ④ 推斷出另一個課題
   但分數 < `EXPLICIT_TOPIC_OVERRIDE_SCORE`（16），會改以學生選定的課題重試檢索；明確講出另一個
   課題（「明治維新」24 分、「冷戰」16 分）仍會切換，避免「soft prior」變成無法切換的硬限制。

模擬結果（同一矩陣）：有課題錨點的提問由 16／35 被拒答降至 **0**；無錨點的提問由 7 次拒答降至
**0**（7 次澄清、其餘以一般知識作答並標明），錯課題由 5 條降至 **2** 條（同程度優先取代了另外 3 條），
餘下 2 條都屬上表「只寫二戰」一項。回歸測試見
[tutor-keyword-miss-regression.test.ts](../tests/tutor-keyword-miss-regression.test.ts)。

## 7. 2026-11-11 追加：真實模型對答模擬的五個決策點

以 16 輪真實 DeepSeek 對答（粵語／簡體／英文／比較／評價／離題／要求代做功課／虛構前提／追問依據）
模擬後，修正了四個缺口，並把「依據查詢」變成零模型呼叫的固定回應。

1. **明確專名可以蓋過 soft prior**（④）：詞庫以 `topicId` 指定，或只對應一個課題的 `課題N` 範疇，
   會標記 `explicitTerm`。切換課題時不再要求分數 ≥ 16；分節關鍵詞及標題片段仍受 16 分門檻限制。
   實測修正：「柏林圍牆幾時拆？」→ 課題10、「希特拉係咪香港人？」→ 課題9、
   「What caused the First World War?」→ 課題9（原本全部被練習課題5 拉回）。
2. **時間背景不算主語**（④）：`explicitTermIsSubject` 會排除「X之後」「X期間」「X前夕」等寫法
   （negative lookahead 排除「後果」「前因」）。「二戰之後有兩個大國互相針對……」仍留在學生
   正在溫習的課題10，不會只因「二戰」二字切到課題9。
3. **soft prior 沒有片段時可用教材內文反推**（④→⑤）：`allowSoftPriorFallback` 只由
   `/api/tutor/chat` 在「練習題課題／對話已保存課題」時開啟；學生自選溫習課題不會開啟，
   改寫詞亦不會觸發（「改寫詞不會令無關段落成為依據」的保證不變）。實測修正：
   「新界係幾時租俾英國？」由「教材未涵蓋」變成課題8（3 段）。
4. **詞庫共現守衛**（③）：`HistoryTermGroup.requiresAny` 要求句中同時出現指定用語。
   「新界」橫跨課題4（五大族）、課題8（租借）、課題12（新市鎮），只有與租借／界址／條約／1898
   等用語同時出現才定位到課題8；《展拓香港界址專條》的範疇由課題6 更正為課題8。
5. **依據查詢不重新推斷課題**（①→直接回覆）：`isTutorEvidenceQuestion` 偵測「有冇課本根據？」
   「你憑咩話係咁？」「邊段教材？」等追問，直接回傳上一則回覆已保存的 `sources` 節錄
   （`evidenceCheck: true`），不呼叫模型、不改課題、不扣額度。實測由 7 秒／引用日本教材，
   變成 27ms／正確列出課題8 的三段原文。
